# 架构与存档

核心规则使用 RefCounted，内容定义使用 Resource，实际地图使用可编辑 TileMapLayer。Godot 场景负责输入与展示，科学计算不读取帧率或物理碰撞结果。

## 模块边界

| 模块 | 当前入口 | 职责 |
| --- | --- | --- |
| 内容 | GameContent 与五类 Def Resource、ChapterManifest | 稳定 ID、卡牌、知识、遭遇、实验及章节定义 |
| 规则 | GameSession.command | 命令校验、权威世界状态、事件提交 |
| 论证 | ModelBattle | 行动预算、证据去重、模型匹配、必需条件 |
| 计算 | ExperimentModel | SI 单位、无阻力解析解、有阻力固定步长积分 |
| 回放 | GameSession.advance 与 echo_poses | 固定时钟、语义事件、位置采样与区域恢复 |
| 持久化 | SaveStore | 校验、临时写入、备份、替换、版本迁移 |
| 展示 | app/main、GameUI、PixelActor、WorldProp | 探索与界面、场景切换、输入映射 |

当前 GameSession 同时承担遭遇路由和轨迹容器；进入第二章前拆出 EncounterRouter、ReplayTrack 与 ChapterRules，并保持序列化协议不变。禁止为了类名数量增加没有职责的包装层。

## 时钟与事件

世界固定 60 tick/s，位置与朝向每 6 tick 采样。开关、箱子、实验、过门等存语义事件。每个已封存历史有独立事件游标和采样游标；未加载的房间依然执行逻辑，场景重新加载后按权威状态绘制。

历史事件按历史列表顺序和各自记录顺序处理，相同输入序列可复现。交互条件不满足时记录因果偏差，游标继续前进。新的历史只收录 actor=player。拾取、对话和奖励不会由回声重复结算；同房间拾取/对话会显示历史回忆提示；专门的动作动画仍待制作。

当前每轮结束封存深拷贝，Demo 保留两轮历史。后续章节最多三个活动回声，其余归档；正式归档格式未在 v0.1 实现。

## 存档协议

schema=2，content_version=1，chapter=fall。外层保存 payload 字符串及 SHA256，内部包含长期 profile、循环、世界、位置、事件、轨迹、历史、游标、卡组与进行中的论证，以及独立检查点。

写入 `.tmp` → 重新解析校验 → 复制原存档为 `.bak` → rename 替换。失败保留原文件，损坏主文件可恢复备份；未来 schema 明确拒绝。schema 1 迁移增加回声采样游标。读取先校验基本类型，不静默重新开始。

区域切换、实验、模型行动边界、循环和结尾保存；转场命令完成后才保存。遭遇 settled 与 completed 标志避免奖励重复提交。主文件未来版本不能用旧备份掩盖。每次格式修改都必须增加旧版固定测试样本。

现有测试覆盖逻辑写入/损坏/备份/迁移，尚不能等同于真实断电和文件系统故障注入。下一次发布前增加权限拒绝、磁盘写满、杀进程中断、未来内容版本、恶意嵌套结构的测试。

## 扩展契约

新增章节必须继承知识和选择，不要求玩家重打。当前章节完成快照已保存，但跨章节导入尚待第二章设计。知识的发现、理解、许可与适用条件最终应分别建模；当前 profile 只记录已理解 ID，不能宣称完整知识权限系统完成。
